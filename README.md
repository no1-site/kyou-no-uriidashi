# 今日の売り出し — ショップ別価格比較

楽天市場で同一商品を確認したうえで、JANコードが取得できる商品はYahoo!ショッピングも横断して価格を比較し、GitHub Pagesで表示します。

## 更新

Windowsの `scripts/run-update-now.cmd` を実行します。保存済み認証情報を使い、最新コードの取得 → 楽天情報の取得 → Yahoo!ショッピング情報の取得（設定済みの場合）→ `products.json` の送信を行います。既存の毎日10:10のタスク登録をやり直す必要はありません。

完了時の `[PRICE RESULT] compared=N reference_only=M` が比較結果です。サイトへの送信成功と、価格比較の成立は別です。`compared=0` の場合は参考商品のみの更新です。

## 比較の方法と範囲

- 商品候補を調べる段階で、家電の交換電池・フィルター・ノズルなどの部品、ホビーの攻略本・主題歌CDなどの関連メディアを商品名から除外します。除外した候補は比較件数の上限に含めません。比較できない場合の参考商品にも同じ選定条件を使います。
- この選定は家電・ホビーを対象とし、洗剤の詰め替えなどは引き続き対象です。商品名の表記に依存するため、本体と付属品を一緒に記載した候補も除外される場合があります。
- 自動取得時の選定除外件数は `collection_summary.categories[].selection_excluded` に記録します。取得済みデータから掲載対象だけを見直した場合は `publication_review` を付け、元の取得日時・各店の価格は更新しません。

- 製品検索APIは製品名・JAN・メーカー・型番の取得だけに使用します。取得できなかった `averagePrice` や新品限定価格には依存しません。
- JAN、またはメーカーと型番で商品検索APIを検索します。検索にヒットしただけでは同一商品と判定しません。説明内のJANの明示、または商品名のメーカーと型番の一致を要求します。
- JANのチェックデジット、型番の末尾、容量・個数、中古・セット・選択式の表記、複数JANや価格のあるページを確認します。互換部品なども除外します。情報不足・曖昧な出品は除外するため、掲載件数が少ない場合があります。販売者の記載が正しいことまでは保証できません。
- 在庫あり・税込表示の出品だけを対象とし、同じショップの出品は最低の商品価格の1件にまとめます。2ショップ以上で比較成立です。同額でもショップ一覧を表示します。
- 「入数／50食」などの数量も照合します。「入数：50」や「●50●」など単位が確認できない出品は、単品・ケース販売のどちらかを推測せず除外します。
- 確認した最高価格が最低価格の3倍を超える場合は、その製品全体の比較を保留します。3倍は再確認のための運用上の基準で、誤価格の断定ではありません。高い店だけを削除して平均を作り直すことはしません。
- 1カテゴリーあたり最大8製品を調べ、比較できた最大2製品を掲載します。商品検索は各検索の先頭30件です。楽天全体を網羅する比較ではありません。
- 送料判定は更新処理と画面で共通の `shipping-policy.mjs` を使います。商品検索APIの出力 `postageFlag` は0が送料込み、1が送料別です（入力の検索条件とは意味が異なります）。商品名に相反する表記、条件付き無料、送料見積もりがある場合は「送料要確認」にします。
- 送料込み表示の店が2店以上あれば、その店同士で平均との差・スコア・過去価格比較を表示します。カードの価格・リンク・ショップ名も、その比較対象の最安店に合わせます。送料別・未確認の店は参考欄に全件残し、平均・スコアに混ぜません。参考欄の方が支払総額では安い場合もあります。APIには配送先別の送料金額がないため、送料を推測して加算しません。送料込み表示も適用条件は販売ページで確認が必要です。
- 数量判定の改訂後は `validation_version: quantity-v2` の結果だけを価格比較として表示します。再取得前のデータは参考表示とし、平均価格・価格差・スコア・過去価格との比較を表示しません。過去価格の計算も同じ版で確認した履歴だけを対象にします。
- 送料込み表示で比較できる商品は、平均との差、ショップ数、レビュー、過去の記録価格からルールでスコアを計算します。アフィリエイト料率は順位に使いません。価格差は値下げ率や購入推奨を意味しません。

価格履歴はWindowsの `%LOCALAPPDATA%\KyouNoUriidashi\price-history.json` に保存します。その他の環境では `.local/price-history.json` です。旧方式の履歴とは別のキーを使い、同日の再実行を履歴の別日として数えません。
送料込み表示の店が2店以上の結果を履歴に追加し、`shipping_policy_version: postage-subset-v2` の履歴だけを過去価格比較に使います。記録価格は送料込み表示の比較対象内の最安価格です。送料別の安値を履歴に混ぜません。

## 診断

`products.json` の先頭要素に `collection_summary` を記録します。カテゴリーごとの検索件数・照合件数・除外理由が分かります。APIキー、リクエストURL、返却データ全体は記録しません。
`shipping_included_compared` が送料込み表示で判定できた商品数、`shipping_price_only` が送料の確認を要する商品数です。`compared` は両方を含むショップ照合済み件数です。取得済みデータを送料条件で再判定した場合は `shipping_review` に記録し、取得日時を変えません。

認証エラー・アクセス拒否・利用制限時は停止し、公開用ファイルは上書きしません。比較できないカテゴリーでは、安さを判定しない参考商品を表示します。

## 検証

Node.js 20以降で `node --test scripts/tests/rakuten-comparison.test.mjs` を実行します。テストは実APIへ接続せず、平均価格がnullのケース、誤比較の除外、ショップの重複排除、障害時の保護、画面表示を確認します。実APIの取得成否はWindowsでの更新後に確認します。

## 公式仕様

送料金額の取得実験は `node scripts/probe-shipping.mjs` で実行できます。2店の公開配送案内から料金候補を抽出する調査用で、毎日の更新処理には組み込んでいません。商品の配送方法や例外との対応は未確定で、抽出金額を支払総額に加算しません。結果と制約は `docs/shipping-feasibility-2026-09-18.md` に記録しています。

- [楽天市場商品検索API](https://webservice.rakuten.co.jp/documentation/ichiba-item-search)
- [商品価格ナビ製品検索API](https://webservice.rakuten.co.jp/documentation/ichiba-product-search)


## Yahoo!ショッピング連携

Yahoo!デベロッパーネットワークでショッピングAPI用のClient IDを発行したら、Windowsで `scripts/setup-yahoo.ps1` を実行します。Client IDはWindowsユーザーに紐づく暗号化ファイルとして `%LOCALAPPDATA%\\KyouNoUriidashi\\yahoo-credentials.xml` に保存し、GitHubには保存しません。

連携後は、楽天側でJANコードまで確認できた掲載商品についてYahoo!ショッピングの商品検索（v3）をJANコードで検索します。在庫あり・新品・同一JANの商品だけを追加し、ストア単位で最低価格を採用します。Yahoo!ショッピングAPIの送料コード2（送料無料）は送料込み表示として扱い、コード1（設定なし）・3（条件付き送料無料）は送料要確認として平均・スコアから除外します。ポイント・クーポンは価格比較に未反映です。

Yahoo!ショッピングAPIは短時間の大量アクセスを避けるため、1リクエストごとに約1.1秒空けます。Yahoo連携が未設定でも楽天のみの更新は継続します。

Yahoo!ショッピングのアフィリエイトIDは現時点では未設定で、まず価格比較を優先します。
