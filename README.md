# 今日の売り出し — ショップ別価格比較

楽天市場の同一商品のショップ別価格を確認し、GitHub Pagesで表示します。

## 更新

Windowsの `scripts/run-update-now.cmd` を実行します。保存済み認証情報を使い、最新コードの取得 → 楽天情報の取得 → `products.json` の送信を行います。既存の毎日10:10のタスク登録をやり直す必要はありません。

完了時の `[PRICE RESULT] compared=N reference_only=M` が比較結果です。サイトへの送信成功と、価格比較の成立は別です。`compared=0` の場合は参考商品のみの更新です。

## 比較の方法と範囲

- 製品検索APIは製品名・JAN・メーカー・型番の取得だけに使用します。取得できなかった `averagePrice` や新品限定価格には依存しません。
- JAN、またはメーカーと型番で商品検索APIを検索します。検索にヒットしただけでは同一商品と判定しません。説明内のJANの明示、または商品名のメーカーと型番の一致を要求します。
- JANのチェックデジット、型番の末尾、容量・個数、中古・セット・選択式の表記、複数JANや価格のあるページを確認します。互換部品なども除外します。情報不足・曖昧な出品は除外するため、掲載件数が少ない場合があります。販売者の記載が正しいことまでは保証できません。
- 在庫あり・税込表示の出品だけを対象とし、同じショップの出品は最低の商品価格の1件にまとめます。2ショップ以上で比較成立です。同額でもショップ一覧を表示します。
- 1カテゴリーあたり最大8製品を調べ、比較できた最大2製品を掲載します。商品検索は各検索の先頭30件です。楽天全体を網羅する比較ではありません。
- 平均は確認した各店の商品価格から計算します。送料の加算、ポイント・クーポンは含めません。送料込み／送料別のAPI表示を各店に併記しますが、配送先などの条件は販売ページで確認が必要です。
- 商品価格の平均との差、ショップ数、レビュー、過去の記録価格からルールでスコアを計算します。アフィリエイト料率は順位に使いません。価格差は値下げ率や購入推奨を意味しません。

価格履歴はWindowsの `%LOCALAPPDATA%\KyouNoUriidashi\price-history.json` に保存します。その他の環境では `.local/price-history.json` です。旧方式の履歴とは別のキーを使い、同日の再実行を履歴の別日として数えません。

## 診断

`products.json` の先頭要素に `collection_summary` を記録します。カテゴリーごとの検索件数・照合件数・除外理由が分かります。APIキー、リクエストURL、返却データ全体は記録しません。

認証エラー・アクセス拒否・利用制限時は停止し、公開用ファイルは上書きしません。比較できないカテゴリーでは、安さを判定しない参考商品を表示します。

## 検証

Node.js 20以降で `node --test scripts/tests/rakuten-comparison.test.mjs` を実行します。テストは実APIへ接続せず、平均価格がnullのケース、誤比較の除外、ショップの重複排除、障害時の保護、画面表示を確認します。実APIの取得成否はWindowsでの更新後に確認します。
